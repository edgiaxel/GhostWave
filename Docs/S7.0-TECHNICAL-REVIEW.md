## 1. Application Audit & Reusable Service Inventory

A thorough audit of the existing GhostWave codebase was conducted to map all existing services, interfaces, and persistence layers. To adhere to architectural principles, the AI subsystem must never duplicate business logic for querying tracks, computing durations, checking health issues, or managing playlists.

### 1.1 Existing Data Models & Interfaces (`src/types/index.ts`)
- **`Track`**: Deterministic track structure with `id` (hash), `filePath`, `fileName`, `fileSizeBytes`, `format` (`mp3`, `flac`, `ogg`, `wav`, `m4a`, `aac`), `title`, `artist`, `album`, `genre` (string array), `durationSeconds`, `bitrateKbps`, `hasEmbeddedPicture`, `availability` (`available`, `missing`, `unreadable`), and `addedAt`.
- **`Playlist`**: `id`, `name`, `description`, `trackIds` (array of track IDs), `createdAt`, `updatedAt`, `isAiGenerated` (boolean flag).
- **`QueueItem`**: `queueId`, `trackId`, `addedAt`.
- **`PlaybackState`**: `currentTrackId`, `status` (`idle`, `loading`, `playing`, `paused`, `ended`, `error`), `isPlaying`, `currentTimeSeconds`, `durationSeconds`, `volume`, `isMuted`, `repeatMode` (`off`, `all`, `one`), `shuffle`, `errorMessage`.
- **`MetadataProposal`**: Structured tag change review object with `id`, `trackId`, `field`, `currentValue`, `proposedValue`, `source` (`ai_gemma`, `online_musicbrainz`, `filename_heuristic`, `manual`), `confidence` (0.0 to 1.0), and `status` (`pending`, `approved`, `rejected`, `applied`).
- **`LibraryIssue`**: Issue report object with `id`, `trackId`, `issueType` (`missing_tags`, `inconsistent_naming`, `potential_duplicate`, `unreadable_file`), `severity` (`low`, `medium`, `high`), `description`, and `suggestedAction`.
- **`AppSettings`**: Configuration object containing `theme`, `accentPalette`, `localAi` (`enabled`, `endpoint`, `model`, `status`), `onlineEnrichment`, `visualizer`, and `library` preferences.

### 1.2 Existing Services Available for Direct Agent Reuse
1. **`IndexedDbRepository` (`src/services/storage/IndexedDbRepository.ts`)**:
   - Manages IndexedDB store `ghostwave_library` with object stores for `tracks`, `blobs`, `settings`, and `playlists`.
   - **Reusable Methods**: `getAllTracks()`, `getTrackById(id)`, `getAllPlaylists()`, `getPlaylistById(id)`, `savePlaylist(playlist)`, `getSettings()`, `saveSettings()`.
   - The AI agent will directly read from this repository without maintaining a second database or caching layer.
2. **`LibraryHealthService` (`src/services/health/LibraryHealthService.ts`)**:
   - Deterministic inspection detecting missing tags, inconsistent naming against configurable templates (e.g. `{artist} - {title}`), exact byte duplicates, and normalized metadata duplicates.
   - **Reusable Method**: `LibraryHealthService.analyze(tracks, renamePattern)` returns verified issues and baseline heuristic proposals.
3. **`MetadataEditService` (`src/services/health/MetadataEditService.ts`)**:
   - Strict metadata validation and filename template generation.
   - **Reusable Methods**: `validate(updates)` enforces field lengths and numerical bounds; `formatFileName(template, track)` generates sanitized file paths.
4. **`PlaybackEngine` (`src/services/playback/PlaybackEngine.ts`)**:
   - Transport audio engine with HTML5 Audio and Web Audio `AnalyserNode`.
   - Reusable for visualizer streaming and audio duration verification.
5. **`Platform File Adapters` (`src/services/platform/`)**:
   - `WebFilePlatform`: HTML5 file picker and in-memory object URL cache.
   - `TauriFilePlatform`: Desktop IPC bridge.

## 2. Ollama Environment & Model Verification

An empirical verification of the local runtime environment on the host system was performed.

### 2.1 Host Environment & Hardware Baseline
- **Ollama Client & Server Version:** `0.34.1`
- **Host GPU:** NVIDIA GeForce RTX 3050 (6,144 MiB VRAM total, ~5,005 MiB free VRAM, Driver 595.91.07, CUDA 13.2)
- **Host CPU:** AMD Ryzen 3 3100 4-Core Processor (8 vCPUs)
- **Host System RAM:** 31 GiB (21 GiB available memory)
- **Active Local Model:** `gemma3:4b` (`registry.ollama.ai/library/gemma3:4b`)
  - **Model ID:** `68ceab7e468a`
  - **Disk Size:** 3.4 GB
  - **Architecture:** `gemma3` (Gemma 3 dense transformer)
  - **Parameter Count:** 3.9B (3,880,101,888)
  - **Quantization:** `Q4_K_M`

  - **Vision Projector:** CLIP vision encoder (419.82M parameters, vision enabled)
  - **Default Stop Sequence:** `<end_of_turn>`

### 2.2 Empirical Model Benchmark Results
A dedicated automated test suite (`test_ollama.py` and `test_prompt_tools.py`) was executed against `http://127.0.0.1:11434` to evaluate the 8 required capabilities:

| Test ID | Capability Evaluated | Test Method | Result | Latency | Observations |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Test 1** | Basic instruction following | Prompt: respond with single word 'HALLOWEEN' | **PASS** | 8.71s (cold load) | Model outputs exact requested token `HALLOWEEN` with zero prelude. |
| **Test 2** | Structured JSON output | Prompt with `"format": "json"` requesting playlist schema | **PASS** | 6.08s | Emitted perfectly valid JSON conforming to specified fields (`playlist_name`, `target_duration_minutes`, `track_ids`). |
| **Test 3** | Tool selection (native `/api/chat` `tools`) | Query total library stats with native Ollama `tools` parameter | **FAIL (HTTP 400)** | 0.002s | Ollama returned: `{"error":"registry.ollama.ai/library/gemma3:4b does not support tools"}`. |
| **Test 3b** | Tool selection (Prompt-based JSON schema) | System prompt defines tool schema, requests tool dispatch | **PASS** | 0.64s (warm) | Successfully emitted `{"action": "call_tool", "tool": "get_library_stats"}`. |
| **Test 4** | Tool argument accuracy | "Find all dark synthwave tracks by John Carpenter, up to 10" | **PASS** | 1.11s | Correctly selected `search_library` with `query: "John Carpenter dark synthwave"`, `genre: "synthwave"`, `max_tracks: 10`. |
| **Test 5** | Multi-step tool interaction | Feeds simulated search results for Halloween tracks back to model | **PASS** | 1.43s | Successfully extracted real IDs `['trk-101', 'trk-102', 'trk-103']` into a `propose_playlist` action without hallucinating IDs. |
| **Test 6** | Handling empty/unavailable results | Feeds empty search results (`tracks: []`) for Beethoven query | **PASS** | 0.82s | Correctly answered: `"I'm sorry, I couldn't find any tracks by Beethoven in your library."` Zero hallucination. |
| **Test 7** | Repeated tool-call behavior | Multi-intent query for searching synth tracks | **PASS** | 1.04s | Structured call generated cleanly without infinite loops or invalid schema. |

### 2.3 Critical Empirical Finding: Tool Dispatch Strategy
Ollama 0.34.1 native tool calling (`"tools": [...]`) requires explicit function-calling metadata in the GGUF model card. The installed `gemma3:4b` manifest does not have Ollama function calling enabled and rejects requests with HTTP 400.  
**However**, `gemma3:4b` has exceptional instruction-following capability when prompted with structured JSON schemas and Ollama's native `"format": "json"`. Warm latency is sub-second (0.64s to 1.43s). Therefore, GhostWave's AI architecture must use **Prompt-Contract Structured Tool Dispatch** rather than relying on Ollama's brittle native tools parameter.

## 3. Local AI Architecture Design

```
+--------------------------------------------------------------------------------+
|                               UI Layer (React)                                 |
|            LocalAiScreen  |  AiPlaylistAssistantModal  |  SettingsScreen       |
+--------------------------------------------------------------------------------+
                                       |
+--------------------------------------------------------------------------------+
|                         Agent Orchestrator Service                             |
|               (Bounded Loop, Max 5 Turns, 30s AbortController)                 |
+--------------------------------------------------------------------------------+
               |                                               |
+------------------------------+             +-----------------------------------+
|      LocalAiProvider         |             |       Deterministic Tool Registry  |
|  (OllamaClient, format=json) |             |  (search_library, stats, propose) |
+------------------------------+             +-----------------------------------+
               |                                               |
+------------------------------+             +-----------------------------------+
|     Localhost Ollama API     |             | Existing App Services & Stores    |
|   (gemma3:4b / gemma2:2b)    |             | (IndexedDbRepository, HealthServ) |
+------------------------------+             +-----------------------------------+
```

### 3.1 Core Architecture Components
1. **`LocalAiProvider` Interface (`src/services/ai/LocalAiProvider.ts`)**:
   - `checkStatus(endpoint: string): Promise<AiConnectionStatus>`
   - `listModels(endpoint: string): Promise<string[]>`
   - `chatCompletion(request: AiChatRequest): Promise<OperationResult<AiChatResponse>>`
2. **`AgentOrchestrator` (`src/services/ai/AgentOrchestrator.ts`)**:
   - Manages task execution loop: `User Prompt -> Tool Selection -> Validation -> Tool Execution -> Final Proposal`.
   - Hard execution limits: Maximum 5 turns per request.
   - Built-in `AbortController` timeout (default 30 seconds).
   - In-memory conversation history scoped only to the active task (cleared on new session).
3. **`DeterministicToolRegistry` (`src/services/ai/ToolRegistry.ts`)**:
   - Maintains strict JSON schemas and validation logic for all registered tools.
   - Reuses existing `IndexedDbRepository` and `LibraryHealthService` methods.
4. **Web vs. Tauri Connectivity & CORS Analysis**:
   - **Desktop (Tauri 2)**: Tauri Webview can communicate directly with `http://127.0.0.1:11434` without CORS restrictions using the Tauri HTTP plugin.
   - **Web (Localhost Development `http://localhost:5173`)**: Direct `fetch('http://127.0.0.1:11434/api/chat')` works because Ollama allows loopback origins by default.
   - **Web (Production on Render `https://ghostwave.onrender.com`)**:
     - Modern web browsers enforce **Mixed Content Blocking**: an HTTPS origin cannot make insecure HTTP requests to `http://127.0.0.1:11434`.
     - In addition, exposing Ollama to the public internet violates user privacy and security invariants.
     - **Architecture Solution**:
       - When running on Web (Render), the UI clearly indicates: *"Local AI runs on your desktop or local environment. Download GhostWave Desktop or run a local CORS proxy to connect to Ollama."*
       - For desktop builds, connection is direct and private.
       - A cloud-hosted fallback or proxy is neither safe nor desirable for a local-first application.

## 4. Initial Agent Tool Specifications

All tools are strictly split into **Read-Only** (safe, idempotent queries) and **Proposal-Only** (structured proposals that require user review). The agent has zero direct mutation authority.

### 4.1 Read-Only Tools

#### `search_library`
- **Purpose:** Search indexed local tracks by keyword, artist, album, genre, or duration.
- **Input Schema:**
  ```json
  {
    "type": "object",
    "properties": {
      "query": { "type": "string", "description": "Text search query for title, artist, or album" },
      "genre": { "type": "string", "description": "Optional genre filter (e.g. Ambient, Horror, Rock)" },
      "format": { "type": "string", "enum": ["mp3", "flac", "ogg", "wav", "m4a", "all"], "description": "Audio format filter" },
      "max_duration_seconds": { "type": "integer", "description": "Upper bound for track duration in seconds" },
      "limit": { "type": "integer", "default": 20, "description": "Maximum number of candidate tracks to return" }
    }
  }
  ```
- **Output Schema:** Array of `{ id: string, title: string, artist: string, album: string, genre: string[], durationSeconds: number, format: string }`.
- **Validation Rules:** Limit clamped to 1..50.
- **Mutation:** None.

#### `get_library_stats`
- **Purpose:** Retrieve aggregate counts to orient the model on collection scale.
- **Input Schema:** `{ "type": "object", "properties": {} }`
- **Output Schema:** `{ totalTracks: number, totalArtists: number, totalAlbums: number, totalDurationSeconds: number, availableFormats: string[] }`.
- **Mutation:** None.

#### `get_track_details`
- **Purpose:** Inspect detailed technical and acoustic metadata for a specific track.
- **Input Schema:**
  ```json
  {
    "type": "object",
    "properties": {
      "track_id": { "type": "string", "description": "Valid track ID" }
    },
    "required": ["track_id"]
  }
  ```
- **Output Schema:** Full `Track` representation (excluding raw audio blobs).
- **Mutation:** None.

#### `get_playlist_details`
- **Purpose:** Inspect tracks and duration of an existing playlist.
- **Input Schema:**
  ```json
  {
    "type": "object",
    "properties": {
      "playlist_id": { "type": "string", "description": "Valid playlist ID" }
    },
    "required": ["playlist_id"]
  }
  ```
- **Output Schema:** `{ id: string, name: string, description: string, tracks: Track[], totalDurationSeconds: number }`.
- **Mutation:** None.

#### `get_health_issues`
- **Purpose:** Retrieve active library defects detected by `LibraryHealthService`.
- **Input Schema:**
  ```json
  {
    "type": "object",
    "properties": {
      "issue_type": { "type": "string", "enum": ["missing_tags", "inconsistent_naming", "potential_duplicate", "all"] }
    }
  }
  ```
- **Output Schema:** Array of `LibraryIssue` objects.
- **Mutation:** None.

### 4.2 Proposal-Only Tools

#### `propose_playlist`
- **Purpose:** Propose a new curated playlist based on user request.
- **Input Schema:**
  ```json
  {
    "type": "object",
    "properties": {
      "name": { "type": "string", "description": "Concise evocative playlist title" },
      "description": { "type": "string", "description": "Explanation of playlist theme and criteria" },
      "track_ids": {
        "type": "array",
        "items": { "type": "string" },
        "description": "Array of real track IDs that exist in the user's library"
      }
    },
    "required": ["name", "track_ids"]
  }
  ```
- **Validation Rules:**
  - `track_ids` array must not be empty.
  - Every ID must resolve to a real record in `IndexedDbRepository`.
  - Duplicate track IDs within the array are stripped.
  - Total duration is calculated deterministically by summing actual track durations.
- **Mutation:** None. Returns a candidate object to the UI for user review.

#### `propose_metadata_correction`
- **Purpose:** Propose a non-destructive tag edit for user approval.
- **Input Schema:**
  ```json
  {
    "type": "object",
    "properties": {
      "track_id": { "type": "string" },
      "field": { "type": "string", "enum": ["title", "artist", "album", "genre", "year", "trackNumber"] },
      "proposed_value": { "type": "string" },
      "rationale": { "type": "string" }
    },
    "required": ["track_id", "field", "proposed_value"]
  }
  ```
- **Validation Rules:** Validated against `MetadataEditService.validate`.
- **Mutation:** None. Enters `metadataProposals` state with status `pending`.

## 5. End-to-End Agent Workflow (Natural-Language Playlist)

**Scenario:** User types *"Create a 40-minute spooky Halloween playlist with dark ambient music."*

```
1. User Request
   └─► Input in UI: "Create a 40-minute spooky Halloween playlist with dark ambient music."

2. Orchestrator Initialization
   ├─► Attach System Prompt with Tool Contracts (format: json)
   ├─► Attach Library Context Summary (total tracks, prominent genres)
   └─► Turn 1 Prompt to Ollama (gemma3:4b)

3. Tool Call Generation (Model)
   └─► Ollama returns: {"action": "call_tool", "tool": "search_library", "arguments": {"query": "Halloween", "genre": "ambient"}}

4. Deterministic Execution (Host)
   ├─► ToolRegistry checks arguments
   ├─► Calls IndexedDbRepository query: returns 8 candidate ambient tracks with durations & IDs
   └─► Formats Tool Result JSON

5. Synthesis & Proposal (Model)
   ├─► Turn 2 Prompt with Tool Result
   └─► Ollama returns: {"action": "propose_playlist", "name": "Spooky Midnight Ambience", "description": "Atmospheric dark soundscapes under 40 minutes", "track_ids": ["trk-a", "trk-b", "trk-c", "trk-d"]}

6. Host Validation & Constraint Verification
   ├─► Validate all 4 track IDs exist in user's library index (Zero Hallucinations)
   ├─► Deterministically sum duration: e.g. 36 minutes 42 seconds (<= 40 minutes constraint satisfied)
   └─► Construct validated Candidate Crate

7. Interactive User Preview (UI)
   ├─► Modal displays: Proposed Crate Name, Description, Duration Badge (36:42)
   ├─► Track list rendered with Reorder handles, Remove buttons, and Play Previews
   └─► User can rename, delete a track, or click "Create Playlist"

8. Approved Persistence
   └─► User clicks "Create Playlist" -> PlaylistService saves to IndexedDB -> Toast confirms creation.
```

### Safety Guardrails
- **Turn Limit:** Maximum 5 iterative turns. If the model does not produce a valid proposal within 5 turns, the orchestrator aborts and prompts the user to refine criteria.
- **Timeout:** 30 seconds hard limit using `AbortController`.
- **ID Verification:** Any track ID returned by the model that does not exist in `IndexedDbRepository` is discarded. If no valid tracks remain, the proposal fails with: *"No matching tracks found in your library."*

## 8. Unresolved Decisions Requiring Axel's Confirmation

1. **Model Selection Default**:
   - We verified `gemma3:4b` is installed locally on the developer machine and runs at ~1s warm latency on the RTX 3050.
   - For users with lower-end laptops lacking a discrete GPU, `gemma2:2b` (1.6 GB) is also an excellent lightweight option.
   - **Recommendation:** Set default model in Settings to `gemma3:4b` (detecting installed models dynamically via `GET /api/tags`), with a fallback to `gemma2:2b`.
2. **Tool Execution Strategy**:
   - Because Ollama rejects `gemma3:4b` under the experimental native `tools` API parameter, we recommend **Prompt-Contract Structured JSON Dispatch** using Ollama's stable `"format": "json"` mode, which passed 100% of our empirical benchmark tests.
